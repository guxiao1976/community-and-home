# Frontend Design 技能使用模板

## 技能名称
`frontend-design`

## 功能描述
生成现代化的 Vue 3 UI 组件和页面布局，包含完整的交互逻辑和样式。

## 使用场景
- 开发新功能页面
- 设计复杂表单或数据展示界面
- 重构现有组件以提升用户体验
- 创建可复用的业务组件

## 输入要求

### 必需信息
- 功能描述（清晰说明页面/组件的用途）
- UI 需求（布局、交互、数据展示方式）
- 技术栈（Vue 3 + TypeScript + Element Plus）

### 可选信息
- 设计参考（类似页面的截图或链接）
- 特殊要求（响应式、可访问性、国际化等）
- 业务规则（表单验证规则、数据处理逻辑等）

## 输出内容
1. Vue 3 单文件组件 (.vue)
2. TypeScript 类型定义
3. 组件使用说明
4. 设计决策说明

## 调用示例

### 示例 1: 用户列表页面
```
为用户管理模块设计一个用户列表页面，包含以下功能：
- 顶部搜索区域（手机号、昵称、状态筛选）
- 表格展示用户信息（头像、手机号、昵称、小区、状态、创建时间）
- 分页组件
- 批量操作（导出、禁用/启用）
- 单行操作（编辑、删除）

技术要求：
- 使用 Element Plus Table 组件
- 响应式设计，支持桌面和移动端
- 确保可访问性 (WCAG 2.1 AA)
```

### 示例 2: 权限配置表单
```
为权限管理模块设计一个角色权限配置表单：
- 角色基本信息（角色名、描述）
- 树形权限选择器（支持全选/反选/搜索）
- 权限预览区域（已选权限的卡片展示）
- 表单验证（角色名必填、至少选择一个权限）

技术要求：
- 使用 Element Plus Form + Tree 组件
- 支持动态加载权限树
- 保存前二次确认
```

### 示例 3: 数据可视化仪表盘
```
为监控模块设计一个系统运行状态仪表盘：
- 顶部 KPI 卡片（在线用户数、今日活跃、系统负载、错误率）
- 中部折线图（24小时用户活跃趋势）
- 底部表格（最近错误日志，实时更新）

技术要求：
- 使用 Element Plus + ECharts
- 自动刷新（30秒间隔）
- 支持时间范围筛选
```

## 最佳实践

### 1. 清晰的需求描述
✅ 好的描述：
```
设计一个用户列表页面，包含搜索、筛选、分页功能。
表格列：头像、手机号、昵称、小区、状态、创建时间。
操作列：编辑、删除按钮。
```

❌ 模糊的描述：
```
做一个用户管理页面
```

### 2. 指定技术栈
始终明确技术栈：
- 框架：Vue 3 Composition API
- UI 库：Element Plus
- 语言：TypeScript
- 状态管理：Pinia（如需要）

### 3. 说明特殊需求
- 响应式设计
- 可访问性标准
- 国际化支持
- 性能要求（大数据量、虚拟滚动等）

### 4. 提供业务上下文
```
这是一个社区管理系统，用户分为业主和管理员。
业主只能看到自己的信息，管理员可以管理所有用户。
```

## 与其他技能配合

### frontend-design + webapp-testing
```
1. 使用 frontend-design 生成 UI 组件
2. 使用 webapp-testing 测试交互流程
```

### frontend-design + audit-website
```
1. 使用 frontend-design 生成页面
2. 使用 audit-website 审计性能和可访问性
3. 根据审计结果优化设计
```

## 注意事项

1. **不要期待完美的一次性输出**
   - 技能生成的组件是基础框架
   - 需要根据实际需求调整和优化

2. **保持一致性**
   - 参考现有组件的风格
   - 遵循项目的设计规范

3. **关注可维护性**
   - 组件化设计，避免单个组件过大
   - 清晰的注释和文档

4. **性能考虑**
   - 大数据量使用虚拟滚动
   - 图片懒加载
   - 防抖/节流处理频繁操作

## 常见问题

### Q: 生成的组件样式与项目不一致怎么办？
A: 在调用时明确项目的设计规范，或者提供现有组件作为参考。

### Q: 如何处理复杂的业务逻辑？
A: 将业务逻辑放在 Pinia store 或单独的 composable 中，组件只负责展示和交互。

### Q: 生成的组件可访问性不够怎么办？
A: 明确要求遵循 WCAG 2.1 AA 标准，或在生成后使用 audit-website 检查并修复。
