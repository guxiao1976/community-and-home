# 通用图文发布组件重构（content_posts 通用化 + 内容级审核 + Kafka）

## 问题

B 方案（用户拍板 2026-08-16）：把通知模块升级为通用图文发布组件。设计文档：docs/superpowers/specs/2026-08-16-content-post-design.md。\n\n核心：\n1. notices 迁移 content_posts（RENAME + section_code + text + status + attachment_count + published_at 去 NOT NULL + 弃 community_id）\n2. content_post_scope 多小区关联（复用 notice_scope 模式：post_id+community_id）\n3. content_post_attachments 加 post_id（main_id）+ review_status（附件级审核状态）\n4. attachment_count 审核完整性判定：已审附件数==计数 且 正文通过 → 展示；任一附件 rejected → 不展示\n5. Kafka 引入（docker-compose 新增，本期一并安装）+ content-review topic\n6. moderation-service 扩展消费者：文字先关键字后大模型、图片/pdf 走大模型（后期开发）\n7. 本期 status 默认 approved（无消费者也可见，功能先跑通）\n8. 板块化：notice 首个板块，未来 repair 等\n\n复用原 notice-multicommunity-publish 已确认的可复用设计（D1-D32）：多小区发布/附件安全（白名单+magic-bytes+总量）/权限（网格员多小区/社区管理员选社区展开/物业业委本小区/业主只读）/GetPublishPermission/GetMarqueeNotices/附件 file_id 重生。\n\n原 notice 变更存档，本变更为独立 L 级。
