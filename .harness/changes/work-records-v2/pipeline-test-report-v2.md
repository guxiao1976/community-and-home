## 新问题：P1-5 任务类型自动推断错误

### 问题描述

**现象**: Workflow 将新功能开发任务误判为 `debt`（技术债务）

**影响**:
- Generator 优先修复服务中已存在的问题
- 忽略用户提供的任务描述
- 虽然 QA 通过，但未完成预期功能

### 根本原因分析

**当前逻辑** (harness-pipeline.js):
```javascript
任务类型: debt (auto-inferred)
```

**推断依据**: 可能基于以下因素
1. 服务中存在明显的构建错误（goctl 重复文件）
2. 任务描述中包含大量 task 列表
3. 缺少明确的 `taskType` 参数

**错误点**: 即使传递了明确的任务描述（17 个新功能 task），仍被误判为债务修复

### 修复建议

**方案 1**: 显式传递 `taskType` 参数（推荐）

```javascript
Workflow({
  args: {
    serviceName: "主数据服务",
    serviceDir: "services/master-data-service",
    taskType: "feature",  // 显式指定类型
    task: "..."
  }
})
```

**方案 2**: 改进自动推断逻辑

```javascript
// 在 harness-pipeline.js 中
if (!args.taskType) {
  // 优先级判断
  if (args.task && args.task.includes("Task 1.1:")) {
    args.taskType = "feature"  // 明确的任务列表 = 新功能
  } else if (hasCompileErrors()) {
    args.taskType = "debt"  // 构建错误 = 技术债务
  } else {
    args.taskType = "feature"  // 默认为新功能
  }
}
```

**方案 3**: 完全移除自动推断，强制要求传递 `taskType`
