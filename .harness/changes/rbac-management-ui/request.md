# Request: RBAC管理界面

**用户原话**: 
```
在后台web pc 管理系统中，目前还没有完整的角色管理、权限管理等页面，根据系统中已有的用户进行角色设计、权限设计，不同角色的人能够看到不同的菜单、前端能够看到不同的内容，比如，发布通知，只有授权的人员才能看到相关图标。权限管理要实现接口级的管理，不能仅仅是前端是否展示相关按钮或者内容，这样知道api时，容易绕过去。数据权限一并考虑，只能看到授权了的数据。调用开发流水线来实现。
```

**路径**: OpenSpec

**理由**: 
- 跨2+服务（权限服务 + PC前端 + 可能涉及其他服务的权限中间件）
- 新功能开发（完整的角色管理、权限管理系统）
- 可能涉及Proto变更（角色管理、权限管理的gRPC接口）
- 需求需要澄清（角色设计、权限粒度、数据权限策略）

**涉及服务**: 
- `services/permission-service` — 后端RBAC实现、接口权限控制
- `web/pc` — 管理界面、角色管理页面、权限管理页面、菜单权限控制
- 其他服务 — 可能需要接入权限校验中间件

**创建时间**: 2026-06-19 08:30

**关键需求点**:
1. 角色管理页面（增删改查角色）
2. 权限管理页面（配置角色-权限关系）
3. 菜单权限控制（不同角色看到不同菜单）
4. 按钮/内容级权限控制（前端展示控制）
5. 接口级权限控制（后端API权限校验，防绕过）
6. 数据权限控制（只能访问授权的数据）
