### 阶段 5：编码管线 ❌ 失败

**执行**: 2 个并行 Workflow (后端 17 tasks, 前端 8 tasks)  
**耗时**: 6 小时 37 分钟  
**结果**: 两个 Workflow 都 `max_iterations_exceeded`（超过最大轮次）

#### 5.1 根本原因分析

**问题**: Workflow 未收到 `task` 参数

**证据**:
1. Owner Agent 调用 Workflow 时传递了完整参数：
   ```javascript
   Workflow({
     args: {
       changeName: "test-pipeline-work-records",
       serviceDir: "services/master-data-service",
       serviceName: "主数据服务",
       task: "Task 1.1: 创建 Migration DDL\nTask 1.2: ...\n..." // 17 个任务
     }
   })
   ```

2. Workflow 输出结果中只包含 `serviceName`，不包含 `task`：
   ```json
   {
     "serviceName": "主数据服务",
     "taskType": "feature",
     "confidence": 0.1
   }
   ```

3. Generator Agent 日志显示：没有读取 `.harness/changes/test-pipeline-work-records/tasks.md`

4. Generator Agent 实际执行内容：修复服务中已存在的问题（文件名大小写冲突、Outbox 事务性问题）

**结论**: Workflow 脚本的 `args` 参数传递机制存在 bug，导致 `args.task` 在 Generator prompt 中未生效。

#### 5.2 Workflow 实际执行内容

**后端 Workflow** (4 轮迭代):
- 第 1 轮: 修复 90+ 个文件名大小写冲突（goctl 重复生成问题）
- 第 2 轮: QA PASS (15/16，仅知识图谱过期)，但 Review 3/3 FAIL（Outbox 事务性、测试覆盖不足）
- 第 3 轮: 继续修复 Review 问题，QA FAIL（知识图谱过期）
- 第 4 轮: 超过最大轮次，终止

**前端 Workflow** (4 轮迭代):
- 第 1-4 轮: 尝试修复已存在的 164 个 TypeScript 构建错误（erasableSyntaxOnly 冲突、aimodel.ts 重复属性）
- 这些错误是历史遗留问题，与本次需求无关
- 超过最大轮次，终止

#### 5.3 Workflow 质量评估（基于实际执行）

**优点**:
1. **QA 机械化检查有效**: 15/16 项检查 PASS，准确发现知识图谱过期
2. **Debug 根因分析准确**: 准确定位知识图谱时间戳问题
3. **Review 3 视角有效**: 发现了 Outbox 事务性、测试覆盖、文档一致性问题
4. **TDD 证据验证**: QA 检查了 RED→GREEN→REFACTOR 流程

**问题**:
1. **参数传递失败** (P0): Generator 未收到任务描述
2. **最大轮次限制过严** (P1): feature 类型任务只允许 3 轮，但复杂问题需要更多轮次
3. **Review 门槛过高** (P2): 要求 2/3 PASS，但 Reviewer 可能对历史债务过于严格
4. **历史问题干扰** (P2): 服务中已存在的问题会干扰新功能开发

**评分**: 1/5（流程设计良好，但参数传递 bug 导致完全不可用）

## 6. 修复建议优先级

### 立即修复（本周）

1. **P0-1: 修复 Workflow 参数传递**
   - 位置: `.harness/workflows/harness-pipeline.js`
   - 原因: `args.task` 未正确传递到 Generator prompt
   - 验证: 添加日志输出 `args` 对象，确认 `task` 字段存在
   - 测试: 用简单任务（如"添加一个 Hello World 端点"）验证

2. **P0-2: 实现工具调用熔断机制**
   - 位置: 子 Agent 系统提示
   - 规则: 连续 2 次相同工具调用失败 → 停止并诊断
   - 参考: `.harness/docs/circuit-breaker.md`

### 短期优化（本月）

3. **P1-1: 调整最大轮次限制**
   - feature 任务: 3 轮 → 5 轮
   - debt 任务: 2 轮 → 3 轮
   - 原因: 复杂问题需要更多迭代空间

4. **P1-2: 隔离历史债务**
   - 新增 `--clean-slate` 模式：只检查本次变更的文件
   - QA 检查时忽略历史问题（非本次修改的文件）

5. **P1-3: 优化 Review 门槛**
   - 当前: 3/3 全部 PASS
   - 建议: 2/3 PASS，且无 CRITICAL 问题

6. **P1-4: 自动化知识图谱同步**
   - 在 QA 检查失败时，自动运行 `graph-sync.sh`
   - 或在 Workflow 启动时预先同步

### 长期改进（本季度）

7. **P2-1: 优化阶段 3 耗时**
   - 当前 43 分钟过长
   - 建议: 并行化任务拆解（后端/前端同时进行）

8. **P2-3: 改进日志追踪**
   - 将 JSONL 转换为结构化 Markdown 日志
   - 提供 Web UI 查看实时进度

9. **P2-4: 进度可视化**
   - 实现 `/workflows` 命令的实时进度显示
   - 显示当前阶段、已完成任务数、预估剩余时间
