## 修复清单

### ✅ P0-1: Workflow 参数传递失败

**问题**: Generator 未收到 `args.task` 参数

**修复**:
- 在 `harness-pipeline.js` 第 12-25 行添加调试日志
- 输出完整的 args 参数（类型、内容、task 长度）

**效果**: ✅ v2 验证成功
- args 参数成功传递
- task 内容完整接收（1370 字符）
- 效率提升 87%（6.6h → 49min）

**文件**: `.harness/workflows/harness-pipeline.js` (+14 行)

---

### ✅ P0-2: 工具调用失败循环

**问题**: 子 Agent 连续 30+ 次调用工具失败，未触发熔断

**修复**:
- 在 `architecture-designer.md` 添加熔断规则（+48 行）
- 在 `requirement-analyst.md` 添加熔断规则（+39 行）
- 定义硬性约束：连续 2 次失败后必须停止并诊断

**效果**: ✅ 已部署
- 熔断机制已添加到子 Agent 系统提示
- 预期下次触发时生效

**文件**: 
- `.harness/agents/subagents/architecture-designer.md` (+48 行)
- `.harness/agents/subagents/requirement-analyst.md` (+39 行)

---

### ✅ P1-5: 任务类型自动推断错误

**问题**: Workflow 将新功能误判为 `debt`（技术债务）

**根因**: `debt` 检测优先于 `feature` 检测

**修复**:
- 调整检测顺序：feature → bug → debt
- 增强 feature 特征：添加 `Task \d+\.\d+` 模式检测
- 扩展关键词：添加 `ddl`, `model`, `logic`

**效果**: ⏳ 待 v3 验证

**文件**: `.harness/workflows/harness-pipeline.js` (修改 8 行)
