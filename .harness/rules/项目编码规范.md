# 项目编码规范

> 稳定约束 · 适用于所有服务和子 Claude 实例 · 最后更新 2026-06-09

---

## 1. 服务间通信

**所有服务间通信必须通过 gRPC 接口**，接口定义在 `api-proto/` 中。

- ❌ 禁止直接访问其他服务的数据库
- ❌ 禁止服务间 HTTP 调用
- ✅ 调用其他服务 → gRPC（etcd 服务发现）

相关记忆：[[grpc-only-comms]]

## 2. Proto 变更权限

**Proto 变更必须在全局 Claude 实例中执行**。子 Claude 实例禁止修改 `api-proto/`。如需修改 proto，子实例应告知用户切换到全局 Claude。

详见 `.harness/rules/Proto管理规范.md`

## 3. common/ 变更影响

**修改 `common/` 会影响所有依赖服务**。涉及 common 的变更需要全局 Claude 评估影响范围。

## 4. go.work 联调规则

本地开发通过 `go.work` 解析模块依赖，修改 common 或 api-proto 后各服务立即可见新代码，无需远程发布。

## 5. Snowflake ID 序列化规范

> JavaScript 安全整数兼容

Snowflake 生成 19 位 ID，超过 JS `Number.MAX_SAFE_INTEGER`（~16 位），JSON 数字解析时精度丢失。

| 层 | 要求 |
|----|------|
| **Proto** | 所有 `int64` ID 字段必须添加 `[jstype = JS_STRING]`，确保 protojson 序列化时以字符串输出 |
| **Go REST API** | 所有 `int64` ID 字段必须使用 `json:"...,string"` 标签 |
| **前端 TypeScript** | 所有 ID 字段类型必须为 `string`，axios 使用 `lossless-json` 解析器 |

> 注意：`repeated int64` 字段也需要加 `[jstype = JS_STRING]`

相关记忆：[[proto-jstype]]

## 6. 提交前机械化检查

任何 `services/<name>/` 下的 Go 代码变更，提交前必须运行：

```bash
bash .harness/scripts/harness-checks.sh --service <name>
```

- 全部 PASS 或仅有已知 WARN → 可以提交
- 有任何 FAIL → **不能提交**，必须先修复
- 适用于全局 Claude 和所有子 Claude 实例，无一例外

相关记忆：[[pre-commit-checks]]

## 7. 密钥与配置

| 规则 | 说明 |
|------|------|
| **密钥统一管理** | `.env`（gitignored）存放真实密钥，`.env.example`（入库）提供模板 |
| **环境变量展开** | 服务配置中 `${VAR}` 由 `configx.MustLoad`（`common/pkg/configx/`）展开 |
| **新服务入口** | 必须用 `configx.MustLoad` 而非 go-zero 原生的 `conf.MustLoad` |
| **RSA 密钥** | PEM 多行格式，暂保留在 YAML 中 |

## 8. 文档约定

### 每个服务必须标配的文件

| 文件 | 优先级 | 作用 |
|------|:---:|------|
| `CLAUDE.md` | 必须 | 启动上下文：角色定位、关键规则、全局公约引用、常用命令 |
| `docs/design.md` | 必须 | 设计决策：数据模型（DDL+ER）、业务流程、接口契约、缓存策略、安全机制 |
| `CHANGELOG.md` | 必须 | 变更历史：每次 PR 记录做了什么、为什么、影响范围 |
| `.harness/knowledge/memory/` | 推荐 | 持久记忆：用户偏好、踩过的坑、技术决策原因 |

### 子 Claude 启动读取顺序

1. `CLAUDE.md` — 知道我是谁、规则、怎么构建
2. `docs/graph-context.md` — Neo4j 知识图谱自动生成的上下文子图
3. `docs/design.md` — 理解数据模型和业务流程
4. `CHANGELOG.md` — 了解变更历史

### CHANGELOG.md 模板

```markdown
# CHANGELOG — <service-name>

## YYYY-MM-DD — <简短标题>

### 做了什么
- <变更1>

### 为什么
<一句话原因>

### 影响
- Proto: <有无 api-proto 变更>
- 调用方: <影响哪些服务>
- 数据库: <有无 migration>
- 关联: <PR/issue 链接>
```

### 文件位置约定

- **服务级文档** → `services/<name>/`（随服务代码存放）
- **跨服务规范** → `docs/specs/`
- **变更追溯索引** → `changes/INDEX.md`
