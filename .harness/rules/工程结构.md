## 服务命名规范

所有 `services/` 下的目录**统一使用 `-service` 后缀**（如 `auth-service`、`user-service`）。

## 服务分层模式

Go 服务遵循 go-zero 的双层模式（`goctl` 生成）：

| 层 | 目录 | 说明 |
|----|------|------|
| **gRPC 入口** | `rpc/` | `zrpc.MustNewServer`，注册到 etcd。`internal/logic/` 业务逻辑，`internal/svc/` 依赖注入 |
| **REST 网关** | `api/` | `rest.MustNewServer`，代理到 gRPC。`internal/handler/` + `internal/logic/` |
| **数据模型** | `model/` | GORM 数据库模型 |

例外：
- `auth-service` / `permission-service` → RPC-only（无 REST 层）
- `moderation-service` → 有 REST 层
- `ai-model-service` → Go+Python 混合

## Proto 组织（`api-proto/`）

使用 Buf v2 管理：

| Proto | gRPC Service | 消费方 |
|-------|-------------|--------|
| `api/auth/v1/auth.proto` | `AuthService` | auth-service |
| `api/user/v1/user.proto` | `UserService` | user-service, auth-service |
| `api/permission/v1/permission.proto` | `PermissionService` | permission-service |
| `api/aimodel/v1/ai_model.proto` | `AiModelService` | ai-model-service, moderation-service |

## 服务间 gRPC 依赖

```
auth-service ──gRPC──> user-service (GetUserByPhone, CreateUser, UpdateUser)
permission-service ——> 独立（无出站 gRPC 调用）
master-data-service ——> 独立（无出站 gRPC 调用）
moderation-service ——> 直接读 masterdata_db 数据库（⚠️ 架构债务，非 gRPC）
ai-model-service ——> 独立（不在 go.work，独立 GitHub org）
```

## 错误码规范

- 格式：5 位 `XXYYY`
- `XX` = 服务中心：99=Common, 10=User, 50=Auth, 06=Permission, 07=File, 30=AI, 40=Moderation
- `YYY` = 具体错误（001-999），`0` = 成功
- HTTP 响应：成功 `{code:0, msg:"success", data:<payload>}`，失败 `{code:<5-digit>, msg:"<desc>", data:null}`
- gRPC 响应嵌入 `BaseResp` 为首字段
