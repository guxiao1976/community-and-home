# 每次代码变更必须执行验证清单

## 为什么会有这条经验

多次出现"改了后端忘了前端"、"改了新增忘了编辑"、旧进程未重启导致新代码不生效等问题。根因是改完代码缺少系统性的验证步骤。

## 强制验证清单（每次变更后必须逐项确认）

### A. 影响面分析（改之前）

动手前先列出：
- 这个改动影响了哪些文件？
- 这些文件涉及哪些代码路径（新增/编辑/删除/查询/测试）？
- 是否有前端对应的页面/组件需要同步？
- 是否有数据库 schema 或配置需要同步？

### B. 代码验证（改之后）

| # | 检查项 | 命令/方法 |
|---|--------|----------|
| 1 | 编译通过 | `go build ./...`（Go）/ `npx vue-tsc --noEmit`（前端） |
| 2 | 测试通过 | `go test ./...`（Go 后端） |
| 3 | 新旧路径都覆盖 | 新增流程 + 编辑流程 + 删除流程，逐一走一遍 |
| 4 | 前后端对齐 | 后端改了字段，前端类型和传参也要改 |

### C. 部署验证（部署后）

| # | 检查项 | 方法 |
|---|--------|------|
| 1 | 旧进程是否已杀掉 | `ps aux \| grep <service>` 确认旧 PID 不存在 |
| 2 | 新进程是否在运行 | `curl` 健康检查端点 |
| 3 | 新代码是否生效 | 检查二进制文件时间戳，或请求一个能体现新行为的端点 |
| 4 | 实际走一遍流程 | 浏览器里完整操作一遍（新增→编辑→删除→测试） |

### D. 常见遗漏场景（重点检查）

| 场景 | 容易漏的 |
|------|---------|
| 改了后端 API 字段 | 前端类型定义、前端传参、前端展示 |
| 改了新增流程 | 编辑流程是否也生效 |
| 改了数据模型 | API 响应类型、前端类型、数据库 migration |
| 删了一个模块/层 | 前端对应的 UI、配置、文档 |
| 改了配置/环境变量 | 所有需要该配置的服务是否都更新了 |
| kill 了进程 | 确认真的被杀掉了（`ps aux`），确认新的已启动 |

## 怎么做

改完代码后，对自己说：**"等一下，验证了再交付"**。按上面清单逐项过，任何一项 FAIL 都不能说"好了"。
