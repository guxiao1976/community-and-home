A

纯前端生成

楼号(1-100)、单元(1-5)、房号(按规律生成) 全在前端，不依赖额外 API。
优点：离线可用，响应快
缺点：无法反映实际入住情况

B

API 返回真实数据

楼号/单元/房号由主数据服务 API 返回，仅展示已录入的。
优点：数据准确，可标记已占用房号
缺点：需要后端支持，依赖网络

C

混合模式（推荐）

前端生成全部选项，API 标记已占用/不可选。先做前端生成（快速上线），后续补充 API 标记。
优点：分步落地，体验好
缺点：初期可能选中尚未录入的房号
