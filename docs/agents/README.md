# 多智能体协作开发系统

## 概述

这是一个基于 Claude 的多智能体协作开发系统，通过主智能体协调计划、开发、测试智能体，实现自动化的软件开发流程。

## 系统架构

```
用户 → 主智能体 → 计划智能体 → 任务计划
              ↓
              开发智能体 → 代码实现
              ↓
              测试智能体 → 质量验证
              ↓
              项目完成
```

## 核心特性

- ✅ **任务自动拆分** - 计划智能体将需求拆分为可执行任务
- ✅ **独立开发环境** - 每个任务在独立 worktree 中开发
- ✅ **自动化测试** - 测试智能体自动验证开发成果
- ✅ **智能修复** - 测试失败时自动通知开发智能体修复
- ✅ **状态持久化** - 所有状态保存在文件中，可恢复
- ✅ **进度透明** - 实时报告开发进度

## 快速开始

### 1. 准备需求文档

创建需求文档，例如 `./doc/requirements/user-auth.md`：

```markdown
# 用户认证功能需求

## 功能描述
实现用户注册、登录、登出功能

## 功能需求
1. 用户注册
   - 支持用户名密码注册
   - 密码强度验证
   - 重复注册检查

2. 用户登录
   - 支持用户名密码登录
   - 返回 JWT token
   - 错误次数限制

3. 用户登出
   - token 失效
   - 清理会话

## 非功能需求
- 响应时间 < 100ms
- 密码使用 bcrypt 加密
- 测试覆盖率 > 80%
```

### 2. 启动主智能体

在 Claude Code 中，使用主智能体提示词启动：

```
我需要开发一个功能，需求文档在 ./doc/requirements/user-auth.md
```

### 3. 主智能体自动执行

主智能体会自动：
1. 启动计划智能体生成任务计划
2. 逐个执行任务
3. 对每个任务：
   - 启动开发智能体开发
   - 启动测试智能体测试
   - 如果测试失败，通知开发智能体修复
   - 重复直到测试通过
4. 生成项目完成报告

### 4. 查看结果

所有结果保存在 `./doc/agents/` 目录：

```
doc/agents/
├── task-status.json          # 任务状态
├── project-report.md         # 项目报告
├── plans/
│   └── plan-20260527-100530.md
└── results/
    ├── dev-result-task-001.md
    ├── test-result-task-001.md
    └── ...
```

## 工作流程

### 完整流程

```
1. 用户提供需求文档路径
   ↓
2. 主智能体启动计划智能体
   ↓
3. 计划智能体生成任务计划
   ↓
4. 主智能体读取任务列表
   ↓
5. 对每个任务：
   a. 启动开发智能体（独立 worktree）
   b. 开发完成，返回结果路径
   c. 启动测试智能体
   d. 测试完成，返回结果路径
   e. 如果测试失败：
      - 通知同一个开发智能体修复
      - 同一个测试智能体重测
      - 重复直到通过（最多3次）
   f. 如果测试通过：
      - 更新任务状态
      - 继续下一个任务
   ↓
6. 所有任务完成
   ↓
7. 生成项目完成报告
```

### 状态转换

```
pending → in_progress → testing → completed
                          ↓
                        failed → in_progress (修复)
                                      ↓
                                  testing (重测)
```

## 关键设计

### 1. 智能体隔离

**开发智能体：**
- 每个任务启动一个新的开发智能体
- 使用 `isolation: "worktree"` 独立工作空间
- 避免代码冲突

**测试智能体：**
- 每个任务启动一个新的测试智能体
- 共享测试环境
- 可以访问开发结果

### 2. 智能体复用

**修复场景：**
- 测试失败时，使用**同一个**开发智能体修复
- 使用**同一个**测试智能体重测
- 保持上下文，提高修复效率

### 3. 路径传递

**原则：**
- 智能体之间只传递文件路径
- 不传递大段文本内容
- 减少 token 消耗

**示例：**
```json
// ✓ 正确
{
  "dev_result_path": "./doc/agents/results/dev-result-task-001.md"
}

// ✗ 错误
{
  "dev_result": "大段的开发结果内容..."
}
```

### 4. 状态持久化

**任务状态文件：** `./doc/agents/task-status.json`

**作用：**
- 记录所有任务状态
- 支持中断恢复
- 追踪进度和统计

### 5. 重试机制

**策略：**
- 每个任务最多重试 3 次
- 重试时使用同一个开发和测试智能体
- 达到上限后标记为永久失败

## 优势

### 1. 高效协作

- 多个智能体并行工作（计划、开发、测试）
- 自动化流程，减少人工干预
- 智能修复，快速迭代

### 2. 质量保证

- 每个任务都经过测试验证
- 测试失败自动修复
- 代码质量检查

### 3. 可追溯

- 所有过程记录在文档中
- 任务状态持久化
- 完整的项目报告

### 4. 可恢复

- 状态保存在文件中
- 支持中断后恢复
- 不依赖内存状态

### 5. 可扩展

- 易于添加新的智能体类型
- 易于调整工作流程
- 易于集成其他工具

## 限制

### 1. 串行执行

- 任务按顺序执行，不并行
- 原因：避免代码冲突
- 改进：未来可支持独立任务并行

### 2. 重试上限

- 每个任务最多重试 3 次
- 原因：避免无限循环
- 改进：可配置重试次数

### 3. 环境依赖

- 需要 Docker 环境（数据库、Redis 等）
- 需要 Go 开发环境
- 改进：提供环境自动配置

## 配置

### 智能体配置

```yaml
# 在主智能体中配置
plan_agent:
  model: "opus"          # 使用 Opus 模型
  timeout: 600000        # 10分钟超时

dev_agent:
  model: "sonnet"        # 使用 Sonnet 模型
  isolation: "worktree"  # 独立工作空间
  timeout: 1800000       # 30分钟超时

test_agent:
  model: "sonnet"        # 使用 Sonnet 模型
  timeout: 600000        # 10分钟超时
```

### 重试配置

```yaml
# 在主智能体中配置
retry:
  max_retries: 3         # 最大重试次数
  retry_delay: 0         # 重试延迟（秒）
```

## 故障排查

### 问题 1：计划智能体失败

**症状：** 无法生成任务计划

**原因：**
- 需求文档不存在
- 需求文档格式错误
- 需求描述不清晰

**解决：**
- 检查需求文档路径
- 检查需求文档内容
- 补充需求细节

### 问题 2：开发智能体超时

**症状：** 开发任务超过 30 分钟

**原因：**
- 任务过于复杂
- 技术难题
- 环境问题

**解决：**
- 拆分任务
- 增加超时时间
- 检查开发环境

### 问题 3：测试智能体失败

**症状：** 无法执行测试

**原因：**
- 测试环境未准备
- 依赖服务未启动
- 测试数据缺失

**解决：**
- 启动 Docker 服务
- 准备测试数据
- 检查环境配置
